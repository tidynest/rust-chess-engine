## 1. Summary

What the project is today: an egui desktop GUI plus a terminal CLI that play
chess against a locally installed Stockfish over UCI. Move generation comes from
the `chess` crate, evaluation from Stockfish. There is no engine of the
project's own, despite the repository name.

State of the build:

| `cargo doc` | clean |

| `cargo machete` | 8 unused dependencies across the 3 crates |

The February audit listed 61 items. 60 are still open. The one that changed,
ENG-16, moved from "field never written" to "field written but never read".
Every commit since then was a dependency bump or the edition-2024 move. The
theme integration that root `CLAUDE.md` describes as the next step has not
started; `theme.rs` still has zero readers.

The 8-warning clippy result is itself a finding. The workspace configures
`unwrap_used`, `expect_used`, `indexing_slicing`, `panic` and more, but no crate
has `[lints] workspace = true`, so none of it applies. The code has 11 bare
`.unwrap()` calls and several byte-index slices that would otherwise warn.

Ten things worth doing first, in order:

1. `cargo update`. Clears all 5 RUSTSEC vulnerabilities with no manifest change.
2. Add `[lints] workspace = true` to each crate and fix what appears.
3. Fix the mate-score sign in `stockfish.rs:264` (one line).
4. Send `position startpos moves ...` instead of a bare FEN (section 3.1).
5. Add a promotion picker; today every promotion silently becomes a queen.
6. Fix the undo freeze in vs-computer mode (section 3.2).
7. Tag engine requests so stale `bestmove` replies are dropped.
8. Add `README.md`, `LICENSE`, a CI workflow, `dependabot.yml`.
9. Remove the 8 unused dependencies and the three unimplemented traits.
10. Then do the theme integration, which is unblocked once `ChessApp` loses its
    duplicate colour fields.

### 2.5 Runtime security

Small attack surface. The only process spawned is `stockfish` by PATH lookup
(`state.rs:85`); a rogue binary earlier in PATH is the usual caveat and a
configurable absolute path fixes it. UCI output is parsed by whitespace split;
`parse_uci_move` in `engine_comm.rs:192-204` slices bytes at fixed offsets and
would panic on a multi-byte character, which Stockfish never emits but a future
engine or a PGN import might. All moves are validated against `MoveGen` before
application, so nothing from the engine can corrupt the board.

## 3. Correctness bugs

New findings first, then the still-open criticals from February. File:line
refers to current HEAD.

### 3.1 New, critical or major

**Stockfish never sees the move history or the halfmove clock.**
`request_engine_move` sends `position fen <board>` (`engine_comm.rs:121,145`
via `state.rs:121`). The `chess` crate's `Board` does not store the halfmove
clock or fullmove number; its FEN writer ends every string with a literal
`" 0 1"` (`board_builder.rs:338` in chess 3.2.0). Consequences: the engine
cannot detect threefold repetition, cannot see the 50-move rule approaching,
and will happily shuffle a won endgame into a draw or repeat moves. Fix: send
`position startpos moves e2e4 e7e5 ...` built from
`game_history.current_moves()`. Same fix also makes `ucinewgame` meaningful.

**Every promotion silently becomes a queen.** `try_make_move`
(`board.rs:325-352`) builds a four-character move string, so
`parse_algebraic` yields `promotion: None`. `ChessEngine::to_chess_move`
(`engine.rs:57`) matches on source and destination only, and `MoveGen` yields
promotions in the order Queen, Knight, Rook, Bishop, so the first hit is always
the queen. The February report said promotion is "silently rejected"; it is
silently auto-queened. Underpromotion is impossible from the GUI. The CLI
accepts `e7e8n` correctly.

**Single undo in vs-computer mode freezes the board.** Undo
(`central_panel.rs:133-142`) takes back one ply and sets
`disable_auto_request = true`. The common case, taking back the engine's reply,
lands on the engine's turn. `is_human_turn` (`board.rs:215-226`) then blocks all
input, and nothing clears the flag except a successful human move, New Game, or
changing the engine colour. A second undo unsticks it, but nothing tells the
user that. Undo in vs-computer mode should take back two plies, or the flag
should clear whenever the position is on the human's turn.

**Stale `bestmove` applied to a different position.** Undo and Redo stay
enabled while `engine_thinking`. `apply_engine_move` (`engine_comm.rs:145-164`)
validates the reply only against the current board. If the user undoes during a
search and the stale move is also legal in the new position, it is played
there. Fix: attach a request id (or the FEN) to `GetBestMove`, echo it in
`BestMove`, and drop mismatches. This also needs `EngineCommand::Stop`.

**Mate score sign is discarded.** `stockfish.rs:264`:
`score = if mate_in == 0 { 10000 } else { -10000 }`. Both `mate 3` and
`mate -3` become -10000. The eval bar then shows "M-" for any mate and the
right panel shows "-100.00". Still open from February (ENG-1).

**Castling never gets a check suffix.** `format_move_san`
(`notation.rs:71-77`) returns `"O-O"` or `"O-O-O"` before the `+`/`#` logic at
lines 134-141 runs. A castling move that gives check is shown without it.

**`info string` lines fake a depth-0, eval-0 update.** `parse_engine_line`
(`stockfish.rs:211-212`) routes every `info` line into `parse_info`, which
returns `Info { depth: 0, score: 0, .. }` when no keys match. Stockfish prints
`info string` for NNUE loading and diagnostics, so the eval flashes 0.00 and
depth 0. Match `info string` first and drop it.

**Eval sign is computed against the wrong board.** `poll_engine_responses`
(`engine_comm.rs:46-51`) negates the score when `game_history.current_board()`
has Black to move, at the time the reply arrives. If the user navigated history
while the engine was thinking, the sign is wrong. Fixed by the request-id
change above, which lets the sign be derived from the request.

**`parse_algebraic` underflows on digit input.** `notation.rs:12`:
`(bytes[0] as char).to_digit(18)? as u8 - 10`. The input `"1234"` gives
`to_digit` = 1, then `1 - 10` panics in debug builds and wraps in release. The
CLI passes raw user input straight here. Still open (CORE-4).

**Captured-pieces panel is wrong after any promotion.** `calculate_material`
(`material.rs:38-63`) decrements per-type buckets only when that type is found
on the board. After a white promotion, the pawn bucket reads one short and the
panel shows Black as having captured a pawn. Track captures as they happen, or
diff total piece counts.

## 4. Architecture and code quality

**Two type systems, half applied.** `chess-core` defines its own `Square`,
`Move`, `Piece`, `Color` and a `GameState` trait, then `GameHistory` and
`format_move_san` take raw `chess::Board` and `chess::ChessMove`, and
`ChessEngine::board()` leaks the `Board`. The desktop crate uses both and
converts at six sites with `chess_core::Square::new(..).unwrap()`. Pick one.
If `chess` stays, delete the custom types and use `chess::` everywhere (about
250 lines removed). If `chess` is being replaced, that is the moment to hide
the library fully behind `chess-core`.

**Two sources of truth.** `ChessApp.engine: ChessEngine` and
`ChessApp.game_history: GameHistory` both hold the current position.
`sync_engine_from_history` rebuilds one from the other through a FEN string
round trip, and it is O(n²) because it replays the game from move one for every
move index (`engine_comm.rs:232-244`; same pattern in
`right_panel.rs:260-272`). Drop `engine`; derive everything from
`game_history.current_board()`. Store SAN alongside each move in
`GameHistory` at the time it is made and the rebuild disappears.

**God object.** `ChessApp` has 39 public fields mixing game, UI, engine and
theme state, plus four flags that exist only to patch ordering problems:
`skip_history_rebuild`, `disable_auto_request`, `loop_protection_counter`,
`last_move_count_check`. `create_test_app` in `gui_app.rs:71-116` has to
enumerate all 39 to build a test instance. Split into `Game`, `UiState`,
`EngineLink { tx, rx, state: Idle | Thinking { request_id } }` and give
`ChessApp` a constructor that does not spawn Stockfish.

**Speculative abstractions with no implementation.** `GameStorage`,
`GameRenderer`, `ChessAnalyser` (traits.rs) have zero implementors.
`StorageError` (lib.rs:104-111), `Effect` and `GameResult`
(chess-engine/lib.rs:12-25) have zero uses. `DisplayMode::Unicode` and
`display_board_with_mode` are unreachable from any binary. `serde` feature on
chess-core has no consumer. Delete all of it; add it back when something
implements it.

**Lint configuration is decorative.** See section 1. Once inherited, expect
`unwrap_used` at 11 sites, `indexing_slicing` at `engine_comm.rs:192-204` and
`display.rs`, `panic` at `notation.rs:108` (`unreachable!`), and
`missing_const_for_fn` on most small getters. Decide which of those lints are
actually wanted before turning them on; `missing_const_for_fn` in particular
is noisy for little gain.

**Piece rendering.** `draw_piece` (`board.rs:401-457`) issues 10 text draws
per piece: shadow, 8 outline offsets, the glyph. That is up to 320 text shapes
per frame for a font-based outline effect. Either one shadow plus glyph, or
real piece images. `egui_extras` with the `image` feature is already declared
for exactly this and unused.

**Crate naming.** `chess-engine` contains no engine; it is a UCI client. The
repository name `rust-chess-engine` makes the same claim. `chess-uci` or
`chess-stockfish` would be honest and a README would say so up front.

**Workspace metadata.** Only `edition` is shared. Add `version`, `license`,
`repository`, `authors`, `rust-version` to `[workspace.package]` and inherit
them. The code already needs Rust 1.88 (let-chains in edition 2024,
`is_multiple_of`), so `rust-version = "1.88"` is the honest MSRV.

## 6. Decisions only the owner can make

1. Licence. Nothing can be reused or contributed to until one exists. MIT or
   Apache-2.0 keeps cozy-chess and the current tree compatible; GPL-3.0 opens
   the door to shakmaty.
2. Replace `chess`, and with what. The `failure` advisory is critical-rated
   and the crate is five years dead. shakmaty (GPL, does more) or cozy-chess
   (MIT, does less) or keep and ignore.
3. Keep the custom `chess-core` types or use the library's types directly.
   Ponytail answer: use the library's, delete 250 lines. Keep the wrapper only
   if a library swap is planned, since then it earns its keep.
4. egui 0.36 now or after the theme work. Four minors of API drift; doing it
   before the theme rewrite means touching the colour code once.
5. Default Stockfish threads. 4 is hostile to this laptop; 1 is safe
   everywhere.
